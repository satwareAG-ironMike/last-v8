# last-v8 - 60 degree V12 on an industrial test stand

Interactive Three.js/WebGL simulation of a 60 degree DOHC V12 running on its
industrial test-cell stand. Twelve cylinders in two banks of six: bank L
(cylinders 1,3,5,7,9,11) has its bore axis at azimuth -30, bank R
(2,4,6,8,10,12) at +30 - a 60 degree V (src/engine/spec.js:23-26). Six
crankpins 60 degrees apart, each carrying a pair of side-by-side rods; six
counterweight planes on seven main bearings; twelve power pulses exactly 60
crank degrees apart, 12 per 720 degree cycle. Stroke 8.0 cm (`spec.js:69`),
crank throw 4.0 cm (`spec.js:72`, half the stroke), rod 14.5 cm
(`spec.js:104`), bore tunnel radius 5.1 (`spec.js:113`). Swept volume 7.39 L,
derived from bore, stroke and cylinder count (`idPlateEngine()`), never typed.

Everything you see is generated by code: no downloaded models, no image files,
no loaders, no network. The only dependency is `three`.

The repo slug `last-v8` is history, not a stale claim: the same dimensions,
stand and harness first carried a cross-plane 90 degree V8 (`GATES.md` rows
G1..G7), and the V12 was rebuilt on top of them in the same engine family -
stroke, rod, bore, head and valvetrain geometry and the pan/stand Z planes
were kept on purpose. The V12 evidence is rows G8..G11.

## Run it

```sh
npm install
npm run serve            # http://127.0.0.1:8089/  (port as first argument: npm run serve 8123)
```

`scripts/serve.mjs` is a dependency-free static server with the repo root as web
root and `/` mapped to `public/index.html`. Open the URL in any WebGL2 browser.

## Controls

The panel sits top right (`public/index.html` `#panel { top: 14px; right: 16px }`), the
HUD top left:

| Control | What it does |
|---|---|
| `START` / `STOP` | starts and stops the crank; the button label and `aria-pressed` follow the running authority |
| `RPM CONTROL` | slider 0..4000, bounds read from the animation module's published `RPM_MIN` / `RPM_MAX` |
| `Slow motion` | 1x, 1/4, 1/10, 1/50 - a time factor on the animation, never on the kinematics |
| `CUTAWAY` | one plane through the crank axis; the camera always stands on the side that gets removed |
| `EXPLODED` / `ASSEMBLE` | a chain teardown along each family's own build axis, and its exact inverse |
| `Part inspection` | menu built from the 187 inspectable members the scene itself publishes, plus `INSPECT`, `CLEAR` |
| `RESET CAMERA` | back to the published home pose (`SPEC.view`) |

Viewport:

| Input | What it does |
|---|---|
| drag with the pointer | orbit (yaw wraps, pitch meets the floor guard) |
| mouse wheel | smooth zoom (damped, never a jump) |
| `W` `A` `S` `D` | walk the focus along the camera's own forward / right axes |
| `Q` `E` | rise / sink |
| hold `Shift` | walk boost |
| `R` | RESET CAMERA |
| click a part | PART INSPECTION on the member the ray really hit |

The camera focus cannot leave the walkable volume and the eye cannot drop under the
test-cell floor plate: the floor guard is derived from `SPEC.stand.floorZ`, so
walking under the plate is structurally impossible rather than unlucky.

## How the simulation is built

| Layer | Files | Owns |
|---|---|---|
| Authority | `src/engine/spec.js` | every published dimension: the six-station row the whole engine derives from, banks at az -30 / +30 (60 deg V), six pins 60 deg apart with twin side-by-side rods, seven main bearings, stroke 8.0 cm, rod 14.5 cm, stand geometry, home view |
| Authority | `src/engine/timing.js` | firing order re-derived from the throws as 1-6-5-10-9-2-4-3-8-7-12-11, 60 degrees apart, the four-stroke sequence per cylinder, cam lobe profiles and valve lift |
| Authority | `src/engine/animation.js` | `state.theta` (crank angle), `state.rpm` (`RPM_MIN` 0 / `RPM_MAX` 4000), slow-motion factor |
| Authority | `src/engine/view.js` | the view law as pure math: cutaway plane from the published home pose, explode directions from real assembly axes, part-bank reading - no DOM, no per-part magic number |
| Plumbing | `src/ui/viewControls.js` | applies that law to the live scene graph: the member table (149 members the teardown table separates, 187 inspectable), the mount hardware, and the published `state()` - including `frameRange`, what an inspection asked the rig to stand at |
| Renderer | `src/render/*.js` | block, heads, cranktrain, valvetrain, manifolds (6-into-1 headers, plenum, rail), stand, materials - all procedural |
| UI | `src/ui/cameraRig.js`, `src/ui/panel.js`, `src/main.js` | camera goal-damping and the control surface |

The renderer is driven from one number: the crank angle. `cranktrain.update(deg)` and
`valvetrain.update(deg)` are what place every rod, piston, cam and valve, so the cams
turn at exactly half crank speed because the crank angle is their only input, and a
piston cannot leave its bore because its position is computed from its own crankpin.
Each pin carries one L and one R big end side by side (`SPEC.crank.rodOff` 0.78,
big end 1.3 wide, 0.12 cm of air to the webs), and the throw's angle relative to the
two bore axes is exactly 60 degrees at every crank angle - which is what makes a
60 degree V with 60 degree pins fire evenly.

`src/ui/panel.js` owns no state. Each control reads what the authority already is
(`state.rpm`, `state.slowmo`, `state.running`, `view.state()`) and writes through its
setter; `sync()` re-reads the authorities and repaints the widgets. A widget therefore
cannot disagree with the simulation, which is what lets the gates drive the real
buttons instead of a mirror API.

Surfaces are `MeshStandardMaterial` throughout: 31 material families over 1118
meshes, 1173 normal/roughness/color maps drawn on `<canvas>` in
`src/render/materials.js`, and an environment map built from a `CanvasTexture`
through `PMREMGenerator`. Machined metal, as-cast metal and the stand's
painted/rubber finishes carry different metalness and roughness laws - see the
G7 (V8) and G11 (V12) rows in `GATES.md`.

The artifact's identity is generated from the same authorities: the HUD header,
the page title, the crank part label (pin azimuths out of `SPEC.crank.pinAz`),
the header label (`6 into 1` counted from `SPEC.block.stations`) and the cast
id plate (`V12-60 DOHC 7.4 L`, serial MULE 01) all derive from the spec, so a
label that disagrees with the geometry cannot exist.

## Verify it

| Command | Gate |
|---|---|
| `npm test` | the unit gates: V12 architecture, kinematics, timing, heads, manifolds, stand, camera rig, view controls - 107 tests |
| `npm run smoke` | the page loads in headless Chromium with zero console errors and a rendered WebGL frame (G9) |
| `node test/controls.smoke.mjs` | G10: every control driven through real CDP mouse/key events (V8 row: G6) |
| `node test/screenshots.mjs` | G11: the rendered assembly measured against the authorities at 8 pinned crank angles; writes `shots/` (V8 row: G7) |
| `node scripts/ledger-audit.mjs` | recomputes every `gate-sig` from the recipe and resolves every cited `output-sha256` to the file it names |
| `python3 scripts/ledger-name-evidence.py --prove` | the V8 rows of `GATES.md` are verbatim: pinned against commit `345f71f`, every base row title, claim line, hash and sig survives |

`GATES.md` is the ledger: each row carries `CHECK`, `EXPECT`, and `EVIDENCE` with the
`gate-sig` (first 16 hex of `sha256(CHECK value + "\n" + EXPECT value)`) and the
`output-sha256` of the run that earned it. `tmp/` and `shots/` are gitignored, so
evidence rides in the ledger as recorded hashes. `test/support/browser.mjs` is the
shared headless-Chromium harness (CDP over WebSocket, console/CDP error collection,
watchdog with one shared teardown).

One test law the V12 made explicit: gates measure their authority, never a
remembered number. Menu size is `inspectables().length`, the separated count is
what the published teardown table claims, the hoist is checked by the floor law
it exists to serve - so the same gates held the V8 and hold the V12 without
being edited.
