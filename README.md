# last-v8 - cross-plane 90 degree V8 on an industrial test stand

Interactive Three.js/WebGL simulation of a cross-plane 90 degree DOHC V8 running on
its industrial test-cell stand. Eight cylinders in two banks of four: bank L (cylinders
1,3,5,7) leans to -Y with its bore axis at polar -45, bank R (2,4,6,8) to +Y at +45,
a 90 degree V (src/engine/spec.js:9-12). Stroke 8.0 cm (`spec.js:26`), crank throw 4.0 cm
(`spec.js:29`, half the stroke), rod 14.5 cm (`spec.js:55`), bore tunnel radius 5.1
(`spec.js:64`).

The tree carries the build switch `SPEC.build.variant` beside the geometry, and
`src/engine/layout.js` is the one helper every naming and valvetrain-count reading goes
through: cam, lobe, lifter, pushrod, rocker and cover counts, the 2:1 cam drive, the HUD
engine name and the id plate lines are all generated from the switch. `src/engine/variant.js`
is the one door that sets it: the page address `/?variant=ohv` boots the OHV build, an
unpublished name is refused and named, and with no address the default `dohc` build boots.
The `ohv` small-block beside it - one central 16-lobe cam in the V driven 2:1 from the crank
10.8 cm below the crank centre on the V bisector - is drawn in part: `SPEC.variants.ohv.drawn`
is `true` because the block casts the lifter gallery and the scene stands its 16 lifters in
the 16 bores that gallery machines, that cam is ground to `maxLift / rockerRatio`, and its 16
valves and 16 springs stand on the seats the head machines. `SPEC.variants.ohv.pendingHardware`
is the measured gap that is left - the pushrods, the rockers and the rocker covers. The OHV head
casts none of the iron a DOHC head needs for its cam (issue #46): no bearing columns, caps,
cradles, shells, retainer tabs, cap bolts, cam covers or bucket bores - 101 head meshes against
the DOHC head's 391 - and its bulkheads are machined down to the plane `ohvRockerLayout()`
derives for the rocker shafts.

Everything you see is generated by code: no downloaded models, no image files, no
loaders, no network. The only dependency is `three`.

## Run it

```sh
npm install
npm run serve            # http://127.0.0.1:8089/  (port as first argument: npm run serve 8123)
```

`scripts/serve.mjs` is a dependency-free static server with the repo root as web
root and `/` mapped to `public/index.html`. Open the URL in any WebGL2 browser.

## Controls

The panel sits top right (`public/index.html` `#panel { top: 14px; right: 16px }`), the
HUD top left:

| Control | What it does |
|---|---|
| `START` / `STOP` | starts and stops the crank; the button label and `aria-pressed` follow the running authority |
| `RPM CONTROL` | slider 0..4000, bounds read from the animation module's published `RPM_MIN` / `RPM_MAX` |
| `Slow motion` | 1x, 1/4, 1/10, 1/50 - a time factor on the animation, never on the kinematics |
| `CUTAWAY` | one plane through the crank axis; the camera always stands on the side that gets removed |
| `EXPLODED` / `ASSEMBLE` | a chain teardown along each family's own build axis, and its exact inverse |
| `Part inspection` | menu built from the inspectable members the scene itself publishes: the count is what `node test/controls.smoke.mjs` prints live from `view.inspectables()`, and `test/ledger.test.mjs` forbids restating it here |
| `RESET CAMERA` | back to the published home pose (`SPEC.view`) |

Viewport:

| Input | What it does |
|---|---|
| drag with the pointer | orbit (yaw wraps, pitch meets the floor guard) |
| mouse wheel | smooth zoom (damped, never a jump) |
| `W` `A` `S` `D` | walk the focus along the camera's own forward / right axes |
| `Q` `E` | rise / sink |
| hold `Shift` | walk boost |
| `R` | RESET CAMERA |
| click a part | PART INSPECTION on the member the ray really hit |

The camera focus cannot leave the walkable volume and the eye cannot drop under the
test-cell floor plate: the floor guard is derived from `SPEC.stand.floorZ`, so
walking under the plate is structurally impossible rather than unlucky.

## How the simulation is built

| Layer | Files | Owns |
|---|---|---|
| Authority | `src/engine/spec.js` | every published dimension: bore, stroke 8.0 cm, rod 14.5 cm, bank angle 90 degree cross-plane, crankpin clocking, stand geometry, home view |
| Authority | `src/engine/timing.js` | firing order 1-8-7-3-6-5-4-2 90 degrees apart, the four-stroke sequence per cylinder, cam lobe profiles and valve lift |
| Authority | `src/engine/animation.js` | `state.theta` (crank angle), `state.rpm` (`RPM_MIN` 0 / `RPM_MAX` 4000), slow-motion factor |
| Authority | `src/engine/view.js` | the view law as pure math: cutaway plane from the published home pose, explode directions from real assembly axes, part-bank reading - no DOM, no per-part magic number |
| Authority | `src/engine/oil.js` | the published drilling network: 59 DOHC bores over 431 legs, 18 OHV bores over 66 legs (supply way, galleries, flank legs, head crossings, main/rod/cam feeds, pump, pickup, gauge), every bore with its own drilling radius and the bearing it feeds |
| Authority | `src/engine/coolant.js` | the published water passages: the jacket bands each bank carries water in, the deck risers bored through block and head as one shared window, the head end links and the cross galleries in each head end wall, each face with the cast wall it claims to stand in - and `SPEC.coolant.pending`, which names the pump, thermostat, radiator, hoses and drain this build does not model. Its member census is measured from the drawn tree by the A1-G6 laws, not copied here |
| Plumbing | `src/ui/viewControls.js` | applies that law to the live scene graph: the member table (mapped / moved / inspectable, all three printed live by `node test/controls.smoke.mjs` rather than copied into this file), the mount hardware, and the published `state()` - including `frameRange`, what an inspection asked the rig to stand at |
| Renderer | `src/render/*.js` | block, heads, cranktrain, valvetrain, manifolds, stand, spark plugs, the drawn oil drilling network, the drawn coolant jackets and passages, materials - all procedural |
| UI | `src/ui/cameraRig.js`, `src/ui/panel.js`, `src/main.js` | camera goal-damping and the control surface |

The renderer is driven from one number: the crank angle. `cranktrain.update(deg)` and
`valvetrain.update(deg)` are what place every rod, piston, cam and valve, so the cams
turn at exactly half crank speed because the crank angle is their only input, and a
piston cannot leave its bore because its position is computed from its own crankpin.

`src/ui/panel.js` owns no state. Each control reads what the authority already is
(`state.rpm`, `state.slowmo`, `state.running`, `view.state()`) and writes through its
setter; `sync()` re-reads the authorities and repaints the widgets. A widget therefore
cannot disagree with the simulation, which is what lets the gates drive the real
buttons instead of a mirror API.

Surfaces are `MeshStandardMaterial` throughout: every family and every
normal/roughness/color map is drawn on `<canvas>` in `src/render/materials.js`, and an
environment map is built from a `CanvasTexture` through `PMREMGenerator`. The mesh /
family / map census of the rendered tree is printed by `node test/screenshots.mjs`, in
its material audit line - this file names that gate instead of keeping a copy of its
numbers, because a copy in a doc that never builds a scene is wrong the moment the
geometry moves. Machined metal, as-cast metal and the stand's painted/rubber finishes
carry different metalness and roughness laws - see the G7 row in `GATES.md`.

## Verify it

| Command | Gate |
|---|---|
| `npm test` | the unit gates: kinematics, timing, heads, manifolds, stand, camera rig, view controls, oil-path connectivity (`test/oil.test.mjs`) |
| `npm run smoke` | the page loads in headless Chromium with zero console errors and a rendered WebGL frame |
| `node test/controls.smoke.mjs` | G6: every control driven through real CDP mouse/key events |
| `node test/screenshots.mjs` | G7: the rendered assembly measured against the authorities at 8 pinned crank angles; writes `shots/` |
| `node scripts/ledger-audit.mjs` | recomputes every `gate-sig` from the recipe and resolves every cited `output-sha256` to the file it names |

`GATES.md` is the ledger: each row carries `CHECK`, `EXPECT`, and `EVIDENCE` with the
`gate-sig` (first 16 hex of `sha256(CHECK value + "\n" + EXPECT value)`) and the
`output-sha256` of the run that earned it. `tmp/` and `shots/` are gitignored, so
evidence rides in the ledger as recorded hashes. `test/support/browser.mjs` is the
shared headless-Chromium harness (CDP over WebSocket, console/CDP error collection,
watchdog with one shared teardown).
